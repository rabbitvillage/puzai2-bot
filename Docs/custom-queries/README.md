# Custom Queries『客製化查詢指令』

用需求找指令：想知道什麼，就在下表找對應的查詢名稱。全部都是**唯讀**，不會改到資料。

## 怎麼執行

查主機上（正式在跑的）資料：

```bash
ssh puzai-nl docker exec puzai2-bot python query.py 查詢名稱 [參數]
```

查本機資料庫（本機有 `data/bot.db` 時）：

```bash
.venv/bin/python query.py 查詢名稱 [參數]
```

不帶任何名稱會列出所有可用查詢。

## 查詢清單

| 我想知道… | 查詢名稱 | 參數 | 結果怎麼解讀 | 不能拿結果做什麼 |
| --- | --- | --- | --- | --- |
| 現在商品賣多少、要幾積分 | `商品設定` | 無 | 所需積分或價格為 0 代表該付款方式未開放；名稱是業主自訂的 | — |
| 業主在 `/set` 設定了什麼（收款地址、頻道、主選單訊息） | `業主設定` | 無 | 沒列出的項目代表還沒設定過（使用預設值）；「（未設定）」代表被清除 | 收款地址要以這裡為準核對，不要憑記憶；發現不是自己設定的地址要立刻處理 |
| 某人的 Telegram ID 是多少（例如要加業主） | `最近加入用戶` | 無 | 最近 20 位第一次按 `/start` 的人，新的在上面 | 名稱與帳號是對方自己取的、可以改；加業主前要跟本人確認 ID |
| 誰的積分最多 | `積分排行` | 無 | 前 20 名與目前餘額 | 不能當作「累計獲得」——已兌換扣掉的不算在內 |
| 今天誰簽到了 | `今日簽到` | 無 | 以台北時間的今天為準 | — |
| 每天多少人簽到、發了多少積分 | `每日簽到統計` | 無 | 最近 30 天，新的在上面 | — |
| 某人的積分怎麼來、怎麼用掉 | `用戶積分明細` | 用戶ID | 正數是加分、負數是扣分；「關聯」是簽到日期或訂單編號 | — |
| 某人下過哪些單 | `用戶訂單` | 用戶ID | 最近 50 筆，含狀態 | 狀態是「待付款／已逾期／已取消」的**不可出貨** |
| 客人報訂單編號，查這筆的狀況 | `查訂單` | 訂單編號 | 一筆訂單的完整資料，含下單當時給客人的收款地址與鏈上交易序號 | 只有狀態是「已完成」才可出貨 |
| 現在有哪些單在等付款 | `待付款訂單` | 無 | 期限時間過了會自動變逾期 | **不可出貨**；也不要因為客人說「我付了」就手動當成已付 |
| 最近成交了哪些單 | `已完成訂單` | 無 | 最近 50 筆；USDT 訂單會附鏈上交易序號 | — |
| 有沒有收到錢但對不上訂單的 | `未對應入帳` | 無 | 常見原因：金額付錯、期限過後才付、與本店無關的轉帳 | **不能直接認定是某張訂單的款項**，要拿交易序號與金額跟客人逐一核對 |
| 每天 USDT 收了多少 | `每日USDT實收` | 無 | 依完成日期與商品加總 | 這是「系統對到訂單的金額」，不含未對應入帳，不等於錢包實際餘額 |
| 積分帳有沒有對不起來 | `積分對帳` | 無 | **沒有任何資料列才是正常**；有列出代表餘額與明細加總不符 | 出現資料列時先不要調整任何人的積分，先查原因 |

範例：

```bash
ssh puzai-nl docker exec puzai2-bot python query.py 今日簽到
ssh puzai-nl docker exec puzai2-bot python query.py 用戶訂單 123456789
ssh puzai-nl docker exec puzai2-bot python query.py 查訂單 B261007123456
```

## 自訂查詢

表上沒有的需求，可以直接寫查詢語法（一樣是唯讀，寫成刪除或修改會被資料庫拒絕）：

```bash
ssh puzai-nl docker exec puzai2-bot python query.py --sql "SELECT COUNT(*) AS 用戶數 FROM users"
```

欄位別名若以「時間」結尾，結果會自動轉成台北時間。

## 資料表速查

| 資料表 | 內容 | 重點欄位 |
| --- | --- | --- |
| `users`『用戶』 | 每位用戶與目前積分 | `points` 目前積分 |
| `checkins`『簽到紀錄』 | 每人每天最多一筆 | `checkin_date` 簽到日期（台北時間） |
| `points_ledger`『積分異動明細』 | 每次加減分 | `change` 異動、`reason` 原因、`ref` 關聯 |
| `products`『商品設定』 | 商品A、商品B | `points_cost` 所需積分、`price_units` 價格 |
| `orders`『訂單』 | 所有訂單 | `status` 狀態、`pay_method` 付款方式、`amount_units` 應付金額、`pay_address` 下單當時的收款地址 |
| `payments`『鏈上入帳紀錄』 | 查到的每筆 USDT 入帳 | `order_no` 為空＝沒對到訂單 |
| `settings`『業主設定』 | 業主在 `/set` 設定的內容 | `welcome_text` 主選單訊息、`channel_url` 頻道連結、`usdt_address` 收款地址、`checkin_points` 每日簽到積分 |

代碼對照：

- `status`『訂單狀態』：`pending` 待付款、`paid` 已完成、`expired` 已逾期、`cancelled` 已取消
- `pay_method`『付款方式』：`points` 積分兌換、`usdt` USDT 付款
- `reason`『積分異動原因』：`checkin` 簽到、`redeem` 兌換商品
- 金額欄位（`price_units`、`amount_units`）是「USDT × 1,000,000」的整數；時間欄位是 Unix 秒數。內建查詢已換算好，自訂查詢要自己換算。

## 共通注意事項

1. 查詢結果是「查的那一刻」的狀態；待付款訂單可能下一秒就入帳或逾期，要做決定前再查一次。
2. 出貨只認訂單狀態「已完成」。待付款、已逾期、已取消都不可出貨。
3. 退款、補單、調整積分都沒有自動功能，需人工處理；這個工具只能看、不能改。
4. 「未對應入帳」只記錄「有訂單在等付款的那段時間」查到的入帳，不是收款地址的完整流水帳。
   業主改過收款地址時，舊地址與新地址的入帳都會出現在這裡，核對時要看清楚是哪個地址收到的。
5. 機器人只在有訂單等待付款時才查鏈；要核對錢包實際餘額請以錢包或區塊鏈瀏覽器為準。
